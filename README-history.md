# 2026-11-21：實驗03使用與實驗01相同的五筆模型校正

本次只修改此 Web。ESP32 沿用已支援五筆校正的版本（已核對 `ipillow-ipillow-spp3_BLE_v4_model_m-fix3`／`5d00902`）；若裝置已燒錄該版，不需為此更新重燒。網頁不能自行確認實際燒錄版本，舊版若未確認五筆協定會拒絕保存。

## 操作與資料來源

1. 選受測者，依序校正姿勢一、姿勢五。微調高度並確認穩定後，按「校正完成」。
2. 實驗03改送 `ANCHOR,START,BSHS,5` 或 `ANCHOR,START,BLHL,5`，與實驗01相同。畫面顯示有效取樣進度及各通道失敗掃描次數；實際取樣有效性仍由 ESP32 決定，不能把五筆理解為必定五秒完成。
3. 必須依序收到五筆 ACK、完成狀態、`ANCHOR,QUALITY` 及 `ANCHOR,GET` 的基準，並核對受測者及高度，才保存。波動較大會提示，但與實驗01一樣可保存裝置接受的五筆平均。
4. 校正卡片、校正總覽 SVG 和逐秒／事件 CSV 的 `calibration_json` 都使用裝置讀回的 Monitor／Neck／Head 平均；與 `firmware_calibration_json` 的三通道數值一致。ADC 保留讀回小數，kPa 顯示四位。校正時間為 Web 收到基準的時間，不是每筆取樣時間。即時 P 資料不再覆蓋這組模型平均。
5. 逾時或回覆不符時不覆蓋舊卡片、不視為新校正成功；等待取消確認後重新查詢高度，須等新壓力並重新勾選才能重試。斷線或恢復失敗須重新連線／開啟校正。舊卡片保留供查看，不能取代未確認的裝置基準。

兩姿勢完成後仍須儲存校正總覽、離枕、抽乾恢復開機高度、套用姿勢一高度，再分別記錄兩種睡姿。**實驗03維持每輪20秒**、原雙模型與缺資料規則、逐秒 CSV 41欄、事件 CSV 40欄、結果 SVG 及每輪 PNG。未改為實驗01的35秒條件流程。實驗02／04仍使用各自的單筆校正快照。

目前 pose1_startup 原版沒有前一次 calibration_fix 的外層重試。另在前次 calibration_fix 找到可重現的限制：跨主迴圈等待的 400 ms 重試視窗，可能被較長 DEBUG／BLE 回覆跨過；下次執行時直接發布失敗，尚未再次讀取已就緒的 ADC。此為可重現的程式情境，不能據此斷言使用者當次實機唯一原因。

v2 在明確五筆校正活動中、STANDBY、EXP02_IDLE 且所有氣路輸出關閉時，於同一次 `readPressureSensors()` 內完成一個有上限的三通道掃描：先呼叫原 read_air_pressure 喚醒 ADC；尚未成功的通道等資料腳位就緒後再呼叫原函式。每輪等待視窗 400 ms、以最多 10 ms 的 delay 讓出 RTOS 排程；成功通道不重讀，完成後才交回主迴圈處理 DEBUG／BLE。沒有忙等、沒有取前次掃描湊數。主迴圈在此校正等待期間可能延後處理指令約 400 ms，加上既有系統耗時；此路徑要求氣路全關。400 ms 為程式檢查門檻，不是硬即時保證。

原 500 ms 掃描排程、每輪發布一次的濾波／補零行為、五筆新有效掃描平均、20 秒逾時與高度穩定保護保留。持續失敗通道仍使該掃描無效，不能以顯示中的平均數取代新讀值。正式記錄、開機、氣路、一般監測與舊八筆校正走原路徑。

保留 pose1_startup 的整套開機後套用滿分姿勢一高度流程與 STOP／斷線保護。HX710B.cpp/.h、read_air_pressure、setup、loop、開機／抽氣／充氣函式與時間常數、模型、35 秒／至少 30 筆規則、CSV schema 都不變。pose_cls 僅新增兩個有鎖的唯讀查詢：是否五筆校正活動中、目前擷取筆數；原擷取／模型函式沒有改動。

## 校正進度與錯誤診斷

在既有 ANCHOR,STATUS 查詢回覆之前，五筆校正增加一行：

### 檔案與時間

檔名與每條件一份 CSV＋PNG 不變，CSV 保留既有 **48 欄**。完整一輪共有 60 筆資料列：30 筆 `event_type=pressure` ＋30 筆 `event_type=classification`；依 `elapsed_s` 配對，壓力與分類 ADC 相同。

| 欄位 | 本版意義 |
|---|---|
| `sample_index`／`classification_sequence` | 裝置本輪分類秒序號 1～30 |
| `elapsed_s` | 序號減 1，即 0～29 的秒格；不是瀏覽器收到通知的經過秒數 |
| `timestamp_iso` | 電腦實際收到完整結果的 ISO 時間（含時區）；補取也保留真實收到時間，不改寫成原秒數 |
| `classification_tick_ms`／`classification_sample_ms` | ESP32 原分類／取樣時間，補取不改寫；是開機後毫秒，不等同電腦日曆時間 |
| `time_source` | `esp32_session_second_browser_received_timestamp`，識別本版時間語意 |
| `gap_timeout_ms`／`data_timeout_s` | 記錄結束後允許補取的 3000 ms／3 秒，不再代表 P 訊息間隔中斷門檻 |
| `run_status`／`interruption_reason` | 完成、中斷或提前結束；缺筆為 `classification_missing`，含無效秒為 `classification_invalid` |

CSV 按秒序號排列；補取較早秒數的接收時間可能比下一列晚，這是實際傳輸情況。分析每秒時使用序號／秒格，不能以瀏覽器接收時間重新分箱，也不能把補取誤認為新的推論。壓力圖 X 軸同樣使用 0～29 秒格。既有桌面輸出不改寫。

## 計時與異常

- 不同狀態的點擊立即結束前段並開新段；同狀態重複點擊只留事件，不重設計時。
- 滿30秒提示並嘗試播放提示音，計時畫面停在30秒。分段CSV不再增加該段的秒格；連續CSV、即時壓力及判定仍持續，保留人工label直到下一次按鈕。聲音受瀏覽器權限限制，畫面提示仍可用。
- 提前切換、錯序、重測均保存，不改寫舊段。只有當前待測姿勢滿30秒、緊接著離枕滿30秒才推進。按錯後照實標記，依提示重測。
- 斷線、中止、個人資料／高度／安全狀態改變時停止本輪，保留部分資料。重連後保持離枕並按「重新確認目前高度，準備補測」；高度不符須先由既有控制恢復。開始按鈕下方會顯示待補測姿勢；先按開始啟用按鈕，再以該姿勢躺下並按對應姿勢新增輪次，重新計時30秒，不接續未完成段。已完成五組後重新開始則從姿勢一重測。
- 充氣失敗、回覆逾時或核對高度失敗時第二組保持停用；確認裝置狀態後重新抽乾。測試開始後校正鎖定；換人選另一受測者並重新校正。
- 時間達標與資料完整分開。Web沒有收到新的完整三通道資料時保留缺資料，不能當空枕或拿舊讀值補秒。

## 輸出與回讀

「匯出目前高度CSV」只輸出目前高度的兩份CSV；「儲存全部結果」輸出目前受測者已有資料的各高度，每高度兩份CSV、一張壓力PNG及一份結果SVG。記錄中可保存快照，連續記錄不停止。同高度的補測、錯序及未完成段一併累積，不覆蓋記憶體中的舊輪次。

檔名不放日期時間；以S01為例：

```text
S01_EXP04_姿勢五高度_分段30秒.csv
S01_EXP04_姿勢五高度_連續紀錄.csv
S01_EXP04_姿勢五高度_壓力曲線.png
S01_EXP04_姿勢五高度_結果總覽.svg
S01_EXP04_姿勢一高度_分段30秒.csv
S01_EXP04_姿勢一高度_連續紀錄.csv
S01_EXP04_姿勢一高度_壓力曲線.png
S01_EXP04_姿勢一高度_結果總覽.svg
```

預覽檔名另加 `SIMULATED_`，避免與實機資料混用。既有校正總覽保留 `S01_04_00_校正總覽.svg`。同名檔案存在時，先一次確認整批覆寫；取消不改動任何檔案。覆寫只包含本頁目前累積資料，另一頁／前次實驗請另選資料夾。寫入失敗保留頁面記錄供重試；多檔寫入並非整批交易。

兩份CSV使用同一批逐秒資料：每次狀態標記起依 `[起點, 終點)` 分成1秒格，每格取最後一筆新壓力；切換、停止或快照的最後一格可以不足1秒。分段檔只取各段前30秒，連續檔另含30秒後等待時間，沒有因按鈕或到時而漏掉等待區間。完整接收樣本保留在頁面記憶體供壓力圖使用，CSV只匯出每秒代表值。

分段CSV為12欄；連續CSV另加 `record_phase`，共13欄，不另輸出舊事件CSV：

| 欄位 | 定義 |
|---|---|
| `timestamp` | 電腦收到該筆完整BLE壓力的本機時間，`YYYY/MM/DD-HH:mm:ss.SSS`；缺資料格留空，避免捏造接收時間 |
| `actual_state` | 操作者label：姿勢一～五／離開枕頭；等待時間沿用上次label，不依判定自動更改 |
| `segment_second` | 該筆接收距本次標記的秒數，保留3位小數；缺資料格填該格起點相對秒數，不是全輪秒數 |
| `monitor_kpa`, `neck_kpa`, `head_kpa` | 三通道壓力kPa |
| `monitor_ratio`, `neck_ratio`, `head_ratio` | 各通道目前kPa／該高度個人有人校正kPa |
| `monitor_result`, `majority_result` | 有人／空枕；任一通道無效或缺資料時兩者皆留空 |
| `data_status` | 有效／缺資料／無效 |
| `record_phase` | 僅連續CSV：本段30秒內／30秒後等待 |

兩檔共同列的時間、label、壓力與判定完全相同。滿30秒代表操作時間完成，不保證30筆有效資料。提前切換、補測及錯序都按實際操作保留；比較準確率時應參照結果總覽中的角色及完成狀態。

日期時間來自電腦系統時鐘，沒有改ESP32協定或宣稱取樣同步。按鈕事件當下也讀取系統時鐘；段長仍用 `performance.now()`，電腦自動校時不改變30秒長度。CSV照接收順序輸出，不依可能跳動的系統時間重新排序。畫面最近接收、PNG開始時間及校正總覽顯示本機時間；metadata內部保留有時區的UTC原值。

每高度PNG包含該高度所有輪次，橫軸為首次記錄後經過秒數；中止與補測間保留時間缺口，不連接兩輪曲線。底色區分躺枕／空枕，灰色為30秒後等待。SVG列出各段完整操作秒數、等待秒數、有效秒格與兩種判定的正確／有效數。

為保留追溯資訊又不增加CSV欄位，SVG的 `<metadata id="exp04-records">` 保存 `EXP04_OCCUPANCY_V3`、本機時區、輪次與狀態、規則版本／六門檻／轉換係數、兩組校正及個人資料、各段精確按鈕時間及操作事件；不重複保存逐筆壓力。只匯出CSV時不會另外生成這份SVG；需要完整追溯時使用「儲存全部結果」。

## 操作順序

**姿勢一、姿勢五校正都是開始實驗三的必要條件。** 兩組基準必須屬於同一位受測者，且已由ESP32完成分類基準擷取；只有Web壓力快照或只校正一種姿勢都不能開始。無歷史static6也需要這兩組個人基準；「無歷史」僅表示不使用之前的量測歷史。校正提供既有模型的個人化輸入基準，不會在裝置上重新訓練模型。換人必須重新校正。

1. 完整Web連接配對ESP32，等待正常開機完成，設定個人資料；實驗專區選03、受試者編號及儲存資料夾。
2. 完成姿勢一、姿勢五校正。儲存各姿勢時仍同步擷取ESP32的分類校正基準；保持姿勢直到完成。
3. 按「截圖並儲存校正總覽」。請受試者離枕，按「受試者已離枕，抽乾並恢復開機高度」。收到裝置完成訊息後，按「套用姿勢一高度，準備測試」。沿用原本的裝置確認與高度安全限制。
4. 選本輪實際姿勢一或姿勢五，勾選離枕確認；確認Monitor、Neck、Head壓力持續更新，再請受試者躺下。
5. **頭部接觸枕頭時由操作者按「開始記錄20秒」**。Web只要求近期收到完整三顆ADC，沒有自動判定躺下／離枕的壓力門檻。兩姿勢全程維持姿勢一校正設定高度。
6. Web從按下開始計時並記壓力，先等待 `CLASSIFY,STOP` 回覆，再送 `CLASSIFY,START` 開啟新分類工作，確保不沿用上一輪歷史。收到開始回覆才接受分類資料。
7. 20秒後停止分類。查看資料完整性，按「完成本輪」。受試者先離枕，再換姿勢或重測；重測增加新輪次。「查看輪次」可切回先前表格與曲線。
8. 按「儲存CSV、結果總覽與壓力曲線」。資料在本頁記憶體中，重新整理或離開前務必儲存；寫入失敗會保留資料供重試。

**可以完成一輪就儲存，不必等兩個姿勢都結束。** 每次匯出的是目前受測者在本頁累積的所有輪次，包含提前結束的部分記錄，不是只有「查看輪次」選中的那一輪。新的結果匯出使用新的時間戳檔名；例如第一次只存姿勢一，第二次在姿勢五完成後再存，第二批會同時包含姿勢一與姿勢五。分析時請選定一批，避免跨批重複計入同一個 `run_id`。

正式頁的校正總覽、CSV、結果總覽及曲線都寫入原先選定的同一個資料夾；按儲存時不需要另外選資料夾。完成本輪不會自動寫檔，請等畫面顯示儲存成功再關閉。離線預覽則改用瀏覽器下載位置，見下方說明。

## 每秒顯示與時間定義

- 表格列出第1～20秒，兩模型各自顯示 **Group1／Group2、Group1機率、Group2機率**。Group1＝姿勢1、2；Group2＝姿勢3、4、5。實際姿勢由操作者選擇，與模型預測分開記錄。
- 第n秒採用Web接收時間 `(n−1, n]` 秒內最後一筆新序號分類；同秒多筆保留在事件CSV。時間以按開始為零點，包含操作者與BLE啟動延遲；裝置取樣與推論時間也另存。
- **20秒計時結束不代表收到20筆有效分類。** 啟動確認或傳輸延遲可能使第一秒缺資料；第20秒界線以後收到的結果不納入。本頁不補值、不沿用上一秒，也不將延遲結果挪到別秒。
- 歷史模型前6筆有效樣本顯示「暖機n/6」，第7筆有效樣本才有結果。無效掃描不算有效暖機資料，暖機因此不一定恰好6秒。
- `OK`＝有結果、`WARMUP`＝暖機、`INVALID`＝裝置讀值無效；CSV額外用 `MISSING`＝該秒沒分類、`NOT_RECORDED`＝提前停止後未記錄的秒。沒有有效結果時類別／機率留空，不能當0機率。
- 重複GET回覆與相同序號不重複計入；舊序號／舊工作結果不覆蓋新資料。收到不同的新分類工作會中止本輪；斷線或高度／使用者狀態變更也會中止並保留部分資料。
- 畫面顯示「有分類資料的秒數」及兩模型各自有效秒數；第3、5、10、15、20秒另列比較總覽。記錄中超過3秒沒有新分類會顯示等待新結果。
- 「查看輪次」只切換先前記錄的表格與曲線，不重跑模型或改變氣囊。標籤固定單行；計時器與秒數標記集中排列，窄卡片保留換行以免溢出。

## 匯出檔案與CSV欄位

每次匯出使用 `<受試者>_03_<匯出時間戳>` 前綴：

| 檔案後綴 | 內容 |
|---|---|
| `_逐秒分類.csv` | **41欄，每輪固定20列**，每秒兩模型結果、機率及該分類使用的ADC |
| `_壓力與分類事件.csv` | **40欄**；每輪一列 `run` 資訊，加上每筆 `pressure` 與 `classification` 事件 |
| `_輪次01_壓力曲線.png` 等 | 每輪一張1600×800 PNG，Monitor／Neck／Head三條ADC線，橫軸為開始後0～20秒 |
| `_結果總覽.svg` | 各輪第3、5、10、15、20秒的兩模型類別與輪次狀態；完整機率看CSV |

例如固定一種高度，姿勢一與姿勢五各記錄20秒，最後一起匯出：**2份CSV＋2張壓力曲線PNG＋1張結果總覽SVG**；加上實驗前的校正總覽SVG，共 **2份CSV＋4張圖片＝6個檔案**。逐秒CSV包含兩輪共40列；事件CSV的列數依實際收到的資料筆數而定。

逐秒CSV方便逐秒比較實際姿勢與兩模型預測；事件CSV保留各筆壓力及分類的獨立接收時間，避免將非同步資料假裝成同一次量測。`expected_group` 是依操作者選擇的實際姿勢指定的預期組別；`static_group`／`history_group` 才是模型預測。未收到分類的秒，其分類及對應ADC留空，另外收到的P壓力仍保存在事件CSV。暖機只代表歷史模型尚未可用，不應當成該模型已判錯。

CSV使用UTF-8 BOM、CRLF與雙引號跳脫，機率保留 **0～1**，畫面則顯示百分比。以下為實際欄位順序；兩份CSV均先放18個共同欄位，再放各自欄位，最後放21個結果欄位。

| 18個共同欄位（依序） | 意義 |
|---|---|
| `schema_version`, `data_origin`, `run_id` | 固定 `EXP03_DUAL_V1`；`DEVICE`或`SIMULATED`；本輪識別碼 |
| `subject`, `gender`, `age_years`, `height_cm`, `weight_kg` | 受試者編號、性別、年齡、身高、體重 |
| `actual_pose`, `expected_group` | 操作者選擇的1或5；對應GROUP1或GROUP2，並非模型結果 |
| `fixed_head_cm`, `fixed_neck_cm` | 本輪設定高度，並非新增的實測高度 |
| `run_started_at`, `run_status`, `run_duration_ms` | 開始ISO時間、輪次狀態、實際記錄時長（最多20000ms） |
| `classification_start_ack_elapsed_ms` | 按開始到收到分類START回覆的時間差 |
| `calibration_json`, `firmware_calibration_json` | Web各姿勢校正快照JSON；裝置BSHS／BLHL基準JSON |

裝置基準JSON每組陣列順序固定為 `[MonitorADC, NeckADC, HeadADC, Head設定cm, Neck設定cm]`，其中ADC是裝置擷取的8筆平均；Web校正JSON保留當時單筆壓力快照，兩者不可混用。

| 各自欄位 | 意義 |
|---|---|
| 逐秒CSV：`second`, `classification_count_in_second` | 第1～20秒、該接收區間內的唯一分類筆數；多筆時本列取最後一筆 |
| 事件CSV：`event_type` | `run`／`pressure`／`classification` |

| 21個結果欄位（依序） | 意義 |
|---|---|
| `elapsed_ms`, `received_at` | Web接收時相對開始的毫秒、ISO時間 |
| `session`, `sequence` | 裝置分類工作與結果序號，用來追蹤去重 |
| `tick_ms`, `sample_sequence`, `sample_ms` | 裝置推論tick、壓力取樣序號、裝置取樣時間；裝置時間不是Web時鐘 |
| `monitor_adc`, `neck_adc`, `head_adc` | 分類列＝該次模型輸入ADC；壓力列＝P訊息的ADC，兩者保留各自時間 |
| `static_status`, `static_group`, `static_p_group1`, `static_p_group2` | 無歷史狀態、預測組別與兩組機率 |
| `history_status`, `history_group`, `history_p_group1`, `history_p_group2` | 有歷史狀態、預測組別與兩組機率 |
| `history_count`, `dropped`, `inference_us` | 裝置推論前有效歷史筆數、裝置累計丟棄tick數、推論耗時微秒 |

事件CSV的壓力列不填分類欄位，分類列不拿別的P快照替換模型ADC。曲線由P事件繪製，保留原ADC值；相鄰壓力接收超過3秒則斷線顯示，CSV仍保留所有已收到的P資料。

## 校正基準數值從哪裡來

這個區塊顯示 **ESP32 儲存並透過 `ANCHOR,GET` 回傳的校正基準**，不是當下即時 P 讀值。

| 操作 | 真正開始擷取的按鈕 | 指令／對應基準 |
|---|---|---|
| 使用者 → 初始校正 → 仰躺校正 | 調整到舒適高度、確認到位後按「完成校正」 | `ANCHOR,START,BSHS`，姿勢一 |
| 使用者 → 初始校正 → 側躺校正 | 調整到舒適高度、確認到位後按「完成校正」 | `ANCHOR,START,BLHL`，姿勢五 |
| 實驗三校正 | 儲存對應姿勢校正時 | 既有 `captureFirmwareAnchor()` 同樣送上述指令，也會更新此區塊 |

只按使用者「設定」會送 USER；只開啟「初始校正」會開啟視窗。兩者都不會擷取新的校正基準。實驗二的 Web 壓力快照與此處 ESP32 校正基準是不同的資料流程，不會因為儲存實驗二校正就自動成為此區塊的基準。

配對韌體在開始擷取後等待至少2秒，收集三顆皆讀取成功的8筆原平滑 ADC，確認範圍符合既有穩定條件才取平均；沒有完成則可能逾時。Web只是顯示回傳的結果，沒有重算或替換感測數值。欄位為：

- `pm` → Monitor ADC、`pn` → Neck ADC、`ph` → Head ADC：有人採該校正姿勢時的8筆平均。
- `head`／`neck` → 當時的 Head／Neck **設定高度（cm）**，不是新增的實際高度量測。
- BSHS／BLHL 仍是兩個特定姿勢的個人基準，不是「所有 Group1／Group2 使用者」的平均。

換人須重新完成兩姿勢校正；此處不新增將既有受測者校正直接套用到另一人的功能。

### 校正基準狀態的意思

| 畫面狀態 | 意義 |
|---|---|
| `IDLE` | 待命中，目前沒有正在擷取校正基準；不是錯誤 |
| `WAIT_SETTLE` | 等待壓力穩定 |
| `COLLECTING` | 正在收集校正數值 |
| `DONE` | 本次校正基準擷取完成 |
| `TIMEOUT` | 本次擷取逾時，未完成 |

這一欄是擷取流程進度。是否已經有可用校正基準，請分別看仰躺BSHS／側躺BLHL的完成標記與數值；不能只由IDLE判斷。校正基準姿勢為NONE表示目前沒有指定擷取姿勢。

### ADC_TIME時間公式與備援政策（2026-11-11）

```text
Head calculatedTimeMs = (目標ADC − 1820918) / 2.837681
Neck calculatedTimeMs = (目標ADC − 1878787) / 5.820554

該氣囊 calculatedTimeMs < 0：Head改用30000ms／Neck改用10000ms
其餘 calculatedTimeMs >= 0：commandTimeMs = min(四捨五入為整數ms, 該氣囊安全上限)
Head安全上限 = 136132ms；Neck安全上限 = 50000ms；不補足至開機時間
```

公式使用本設備2026-05-04時間／ADC資料及 `time_2_adc_260507.ipynb` 回歸（依本次提供的係數）；實際設備換算以ESP32為準，Web僅預算並核對裝置回覆。這是新增實驗02控制行為，不變更既有ADC↔kPa係數。

- 只替換負時間的氣囊，並標記「開機基準備援（負時間）」。零秒不充氣；正值即使Head低於30秒、Neck低於10秒也照公式值，畫面標記「低於開機基準」。備援不是個人校正高度，分析時須區分純公式輪與備援輪。
- 理論時間超過既有 Head **136.132秒**／Neck **50秒**時，Web預算與ESP32指令均只對該氣囊使用上限，整輪繼續執行。目標ADC與理論時間不修改，畫面及SVG標記「安全上限截斷」。韌體保留執行期超限的 `FILL_LIMIT`防線；無效或超出接受範圍的目標ADC仍拒絕。
- 固定時間不追ADC、不保證命中壓力目標；時間模式不因壓力目標落差回 `TARGET_OVERSHOOT`等達標錯誤。原 `ADC`閉迴路模式仍留在韌體，但R／M／A按鈕不再使用。
- 原吸乾 → Monitor 14.5秒 → Neck固定時間 → Head固定時間；沿用各通道停泵後與最終5秒緩衝。**緩衝結束不代表壓力穩定**，操作者仍需待穩定再記錄空枕，再讓受測者躺回。

新回覆（所有時間皆為毫秒；Head在前、Neck在後）：

```text
EXP02,ACK,<id>,ADC_TIME
EXP02,TIME,<id>,<head_calculated_ms>,<neck_calculated_ms>,<head_command_ms>,<neck_command_ms>,<head_fallback>,<neck_fallback>
EXP02,DONE,<id>,<head_adc>,<neck_adc>,NA,NA
```

理論時間保留正負號及小數3位，指令時間為整數ms，備援旗標為0或1。`TIME`在ACK之後、充氣之前回傳。Web核對相同輪次、模式、原始公式時間、指令時間、逐氣囊備援旗標；若不一致、缺少TIME或完成欄位不合法，送出STOP並中止。BLE斷線、ACK逾時、整輪逾時及操作者取消繼續沿用既有停止流程。此Web必須配對支援ADC_TIME的新韌體。

3. 等裝置到位、姿勢及壓力穩定、受測者確認滿意度 **10 分**後，勾選確認並按「校正完成」。請受測者換成另一個校正姿勢，再用同樣流程完成姿勢五校正。兩姿勢都保存後，按「截圖並儲存校正總覽」。
4. 在「方法測試」選姿勢一或姿勢五。受測者離枕後勾選確認，按 R／M／A／I 其中一個。每次方法測試都會重新吸乾與充氣。充氣完成後維持空枕，等讀值穩定再按「記錄空枕壓力」。
5. 請受測者**以本輪同一姿勢躺回**。待壓力穩定後按「記錄躺回壓力」，依受測者回覆選 **0～10 分**，再按「截圖並儲存本次結果」。
6. 重複步驟 4–5，完成姿勢一四種與姿勢五四種方法。每位受測者共 **1 張校正總覽＋8 張方法結果圖**。已存的條件可再點方法按鈕檢視及重新存圖。

### 存檔與目前的控制限制

- 兩種截圖都採用與截圖精靈相同的 **SVG** 格式。例如 `S01_00_校正總覽.svg`、`S01_姿勢一_M.svg`、`S01_姿勢五_I.svg`。按截圖後直接存入選定資料夾，同名檔會先詢問是否覆蓋。寫入成功才會更新方法完成進度。重新整理後需再選資料夾，頁面內暫存的校正及進度也會清除，已存的 SVG 保留。
- 操作者確認穩定後擷取當時的一筆有效壓力回報。BLE `P:` 順序為 **Monitor、Neck、Head**。校正總覽包含基本資料與兩個基準。方法結果包含方法、姿勢、校正控制高度、各氣囊充氣設定、空枕與躺回時間、壓力差值及滿意度。
- **方法測試使用實驗 02 專用流程**。R／M／A 以 `ADC_TIME`將目標 ADC 傳給 ESP32，由韌體換算固定充氣時間，時間到即停泵；I 傳送同姿勢的校正控制高度，由韌體換算充氣時間。每次均先吸乾，再固定為 Monitor 14.5 秒，最後處理 Head 與 Neck。網頁等待相同實驗 ID 的 `EXP02,ACK` 與 `EXP02,DONE` 才允許記錄空枕；逾時或裝置回報 `ERR` 會停止該次測試。空枕是否達到目標，仍由操作者待穩定後記錄實測值比較。校正小視窗沿用既有高度微調流程。
- 既有進階文字指令 `MANUAL,FILL,NECK,<ms>`，僅供定時頸部測試；韌體仍執行時間與安全額度檢查。目前已完成部分實機流程檢查，仍需完成R／M／A／I、失敗處理與斷線行為的整套驗收。

## 2026-11-04 Experiment 01 獨立校正（歷史設計）

以下保留 11 月 4 日的設計背景。現版已加入裝置基準擷取、必填個人資料、唯讀本輪高度與姿勢五先測流程；實際操作以本文頂端的 2026-11-16 章節為準。

在 Experiment 01 內容最上方顯示姿勢一／姿勢五的 Head、Neck 高度微調與並列校正紀錄，先校正，再往下填寫本輪設定。姿勢五先帶入 ESP32 依已設定的性別、年齡、身高與體重推估的起始高度，再由操作者微調。實驗區不自動傳送 `USER`、`INIT,NORM,L`、`ANCHOR,START/CLEAR` 或 `MANUAL,ENTER`；原 firmware 與已完成 anchors 不變。

介面已移除備註、試次編號及「將此姿勢已存高度帶入本輪」功能。本輪 Head／Neck 高度由對應姿勢校正自動帶入，操作者仍可修改並須確認。CSV 的 `notes` 與 `trial_index` 保留為空值；原 23 欄順序不變，末尾新增 3 個受試者欄位，共 26 欄，檔名與圖表不再顯示試次，重測以唯一 `run_id` 區分。

上方「使用者資料」目前輸入的年齡、身高與體重會自動顯示在實驗區受試者編號下方。此處讀取的是表單目前輸入值，不代表 ESP32 已確認；不需為帶入資料按上方「設定」，也不會重送 `USER` 或清除 anchors；姿勢五建議高度則另須上方資料已設定到裝置，且收到相符回覆。開始前修改資料會取消本輪確認，請核對受試者編號及資料後重新勾選。

按「開始記錄」時保存三個值，本輪結果摘要、CSV 與線圖 PNG 都使用這份快照。記錄中修改上方欄位不改寫本輪；完成後可看到下一輪使用的新輸入，切回舊條件仍保留舊結果。保存校正快照時，也會記下當下年齡／身高／體重並顯示於各姿勢紀錄，供截圖使用。年齡須為非負整數，身高／體重須為大於零的有限數字並保留小數；空白或無效值顯示「未填／無效」、CSV 留空，不自動填零，也不新增必填限制。

操作順序：

1. 連線後選擇受試者編號（S01～S10），按「校正姿勢一」或「校正姿勢五」，在視窗中自動準備微調並讀取高度。
2. 姿勢一從目前裝置高度開始；姿勢五以相符使用者的裝置建議高度開始，已有草稿則保留。缺少相符建議時不使用固定預設，需先核對上方使用者資料與裝置回覆。
3. 設定 Head／Neck 待套用值，或用 ± 每次調整 0.5 cm；按「套用高度」依序等待 Head、Neck 到位。Head 限 7–16 cm、Neck 限 10–14 cm；單通道套用仍可在「單獨套用與重新讀取」內操作。沿用 `SET,NORM,EXPERIMENT,S,HEAD|NECK,<高度>` 與原到位確認，不重跑啟動充氣。
4. 待受試者自然呼吸、姿勢與壓力穩定且滿意度 10 分，勾選確認並按「校正完成」。需有準備／調整完成後的新鮮完整 P 訊息，待套用值與裝置高度一致；保存後關閉視窗。
5. 對另一姿勢重複操作。兩組卡片並列顯示控制高度與三通道 ADC／kPa；選擇資料夾後按「截圖並儲存校正總覽」，保留完整個人資料、目標／估計高度及壓力接收時間。
6. 選擇對應實驗條件，本輪 Head／Neck 設定高度會帶入該人的對應校正值。若裝置高度尚未正確，重新開啟對應校正視窗調整、確認到位後關閉，再勾選本輪確認、開始記錄。

姿勢五讀取同一份完整 DEBUG 的最終 `HLF`（Head）／`N1LF`（Neck），不使用 `HLF_raw`／`N1LF_raw` 或舊式混合快取，也不在 JavaScript 重寫人體公式。裝置依性別與年齡組別估算體寬，再推估側躺高度；final 值已包含 0.5 cm 步進、安全範圍及初始 Head 不高於 Neck 的策略。Web 核對目前表單與裝置 profile、連線及 3.5 秒回覆新鮮度；缺漏、不符或過期時不產生新預設值，也不退回固定 13 cm。

若新鮮完整回覆確認裝置已換成另一組使用者資料，即使上方表單未變，也會清除舊姿勢五草稿並取消確認。暫時過期、斷線或準備時尚未收到完整資料不會清除同一使用者的手動值；是否允許套用仍由既有連線、到位及新鮮度檢查決定。

裝置 `USER` 以整數處理身高／體重；例如輸入 170.5 cm、65.5 kg，裝置以 170 cm、65 kg 推估，實驗 CSV 仍保留原小數。建議高度橋接只接受一般十進位數字，避免科學記號在 Web 與 firmware 解析不同。上方既有「設定」會送 USER、停止 PRED，且使用者資料變更時會清除舊 anchors；新的實驗帶入功能本身不重送 USER、不自動套用高度，也不更動 firmware。

同步套用全程鎖定重複操作、姿勢／受試者切換及開始記錄。Head 階段若失敗、逾時或斷線，就不送 Neck；已完成的調整不自動復原，需由操作者確認裝置現況。兩個高度都到位後，才可確認穩定並保存快照。

校正快照是**按下保存時最新的一筆完整 P 訊息，不是平均值或模型訓練校正**。「校正完成」只把資料暫存於本頁記憶體並顯示在畫面，不會立即輸出檔案；完成兩姿勢後另按「截圖並儲存校正總覽」保存 SVG。高度是 firmware 依充放氣時間估計，並非高度感測器實測。

快照按受試者編號及姿勢分開暫存，換人不會沿用另一人的快照，切回同一編號可查看其已存紀錄；重存前會要求確認替換。離開／重新整理會遺失記憶體資料，沒有自動存檔或跨重新整理恢復；可用總覽按鈕明確保存 SVG，但 SVG 不會自動匯回本頁。校正時的壓力／高度快照不併入每輪 CSV，也不會出現在每輪壓力曲線 PNG 中；每輪受試者資料另取開始記錄時的值。

`HEIGHT_SET` 僅視為目標 ACK；到位須確認本次命令後完整 DEBUG 的 target/current 及一般待命、氣路關閉的 I 回報。微調等待中禁止重複調整及切換實驗；斷線、逾時、裝置仍在動作、舊 anchor 正在採樣或回報過期時不允許保存。已啟用本區校正的收數流程還會檢查本輪高度與裝置回報一致。

若已校正卻不能開始，請看「開始記錄」上方的具體原因。本輪高度是可自動帶入校正值、仍須人工確認的記錄欄位：例如裝置已到位 Head 9 cm／Neck 11 cm，但本輪 Head 仍填 8 cm，會顯示不符通道及兩個數值；請將本輪記錄改為目前高度並重新勾選確認，不需為修正記錄再次調整枕頭。空白欄位顯示「未填」，高度未就緒則顯示裝置狀態原因。

「Web 未回報自動高度調整啟用」是控制提醒，本身不阻擋開始；未啟用時以一般提示顯示，自動模式或 PRED 啟用時保留警示。BLE、有效壓力訊息、高度一致、表單確認及未匯出保護仍依原條件檢查，自動帶入本輪高度不改動硬體控制。

### 準備微調的停用回覆修正（2026-11-04）

ESP32 在 PRED／POSE 功能已停用時，連 `PRED,STOP`／`CLASSIFY,STOP` 或 GET 都可能回 `ERR,DISABLED`。本版不再把精確的 `PRED,ERR,DISABLED`、`CLASSIFY,ERR,DISABLED` 當成高度操作失敗；其他錯誤仍中止操作。停用回覆本身不代表已準備完成，仍須取得本次準備後的 `FEATURE,STATUS`，確認 PRED／LEGACY 關閉，以及新鮮完整 DEBUG／I、一般待命、氣路全關、無 anchor 採樣及 current＝target。

此 firmware 停用 PRED 後，DEBUG 的 `pre_stage` 可能保留停用前的快取值。仍要求該欄位存在且非空，並保留於診斷資料；其快取值不再單獨阻擋已確認關閉且待命的微調。SET 送出前再檢查功能旗標及裝置狀態；送出後仍須 ACK 與新 DEBUG／I 才確認到位，保留高度上下限、單通道操作、斷線與逾時保護。本次沒有更動 firmware 或協定。

程式驗證使用合成資料，不會連接 BLE 或操控硬體。桌面與 320 px 截圖位於 `tests/.artifacts/chart-browser/SYNTHETIC_calibration-desktop.png`、`SYNTHETIC_calibration-320.png`，只供本機驗證，不提交。

## Experiment 01 壓力資料收集

以下說明壓力收集與欄位，並保留歷史驗證；目前四條件順序、分類啟動與逐輪儲存，以本文件頂端 2026-11-16 章節為準。

實驗專區位於左欄「高度與壓力監測」與「訊息紀錄」之間，九個實驗共用同一個 Hub。首次預設收合；目前提供 Experiment 01～04，05～09 為未設定插槽。Experiment 01 的四種條件在該實驗內選擇。

### 目的與條件

Experiment 01：**固定睡姿下自然呼吸與微動之辨識穩健性測試**。目前同時收集 ESP32 `P:` 三通道 ADC 與 `CLASSIFY,DATA,V1` 雙模型結果，匯出 CSV 與壓力 PNG；分類準確率與穩健性仍需另外分析，不能以顯示 Group 即判定已驗證。

| condition_id | actual_pose | height_condition | test_condition | 操作情境 |
| --- | --- | --- | --- | --- |
| 01 | pose1 | height1 | still | 睡姿一／對應高度／穩定不動、自然呼吸 |
| 02 | pose1 | height1 | movement | 睡姿一／對應高度／微微作動、自然呼吸 |
| 03 | pose5 | height5 | still | 睡姿五／對應高度／穩定不動、自然呼吸 |
| 04 | pose5 | height5 | movement | 睡姿五／對應高度／微微作動、自然呼吸 |

測試依序為條件 03 → 04 → 高度切換 → 01 → 02；姿勢一、五的裝置校正目標分別為 BSHS、BLHL，模型輸出則是 Group1／Group2。每條件各收集一輪 30 秒，四輪合計 120 秒記錄窗口；不含調整姿勢／高度、等待穩定及儲存。自然呼吸不憋氣；微動是同一睡姿的小幅調整，不另制定頻率、幅度或動作腳本。本實驗沒有高度錯配條件。

### 操作者流程

1. 用支援 Web Bluetooth 的瀏覽器開啟 `spp3_BLE/`，連接 ESP32。開始前須已收到至少兩筆完整三通道訊息且資料未過期，這不是自動判定受試者穩定。
2. 選擇 Experiment 01、S01～S10 及儲存資料夾，完成姿勢一、姿勢五校正。每輪自動產生唯一 `run_id`，不需填試次編號。
3. 保留最後的姿勢五高度，畫面自動選姿勢五穩定並帶入校正高度。Head 為 7–16 cm，Neck 為 10–14 cm，步進 0.5 cm；本輪欄位只供核對，不代替裝置高度控制。
4. 按「開始辨識」進入準備狀態，等待期間不顯示或累積分類。確認本輪姿勢／動作及高度後勾選，按「開始記錄」才顯示結果並記錄 30 秒；不另加等待秒數。本輪設定與實驗切換在記錄期間鎖定，收合 Hub 不會停止記錄。
5. 30 秒到時自動停止；按「提前結束」則保留已有資料並標示未完成。檢查曲線、樣本數、分類狀態及本輪快照。
6. 按「儲存本輪 CSV＋線圖」，完成一輪就存一輪。資料夾寫入成功才推進；無資料夾時沿用瀏覽器下載，須確認兩個檔案實際已保存。未儲存資料會阻擋所有下一輪開始；重測前仍會要求確認。
7. 姿勢五穩定／微動都完成儲存後，離枕並按「抽乾並設定姿勢一高度」。高度與基準確認後，依序完成姿勢一穩定、微動的各 30 秒與獨立儲存，詳見頂端流程。

四個條件各自在本頁暫存最後一輪資料與曲線。切到尚未記錄的條件顯示空圖及該條件標題；切回已有紀錄的條件會恢復原曲線與結果快照，並可匯出該輪的 CSV／PNG。輸入表單本身仍共用，每次開始前須重新確認本輪設定。其他條件尚未匯出的結果會顯示提醒，且仍受離頁保護；切換不會丟棄它們。每個條件仍只保留最後一輪，不依受試者保存完整歷史；同條件重測前需先匯出，並確認替換。

明確 BLE 斷線立即標記 `interrupted`；連續 **3 秒**沒有有效完整 P 訊息也中止本輪，不補造資料、不自動續接。這是基於現有每秒 P 查詢的初始門檻，**尚未實機驗證**；請利用顯示的實際接收間隔評估。`data_timeout_s=3` 與 `gap_timeout_ms=3000` 保存於 CSV。

### 訊息、時間與圖表

- 收集入口沿用既有通知分行與 P parser：`P:<pm> <pn> <ph>`，固定對應 Monitor、Neck、Head。只有已換行、恰好三個完整且有限數值的 BLE 回覆成為樣本；不收指令 echo、I／DEBUG 或 100 ms timeout 的未完成片段。網頁保存 P 訊息中的 ADC 數值，不另套校正公式或轉成 kPa。
- 資料域說明：此處保存的是 firmware 處理／濾波後對外回傳的 ADC（filtered ADC），不是感測器未濾波的原始讀值。介面部分沿用的 `raw ADC`／「原始 ADC」指 Web 原樣保存收到的 ADC 數值，不能解讀成未濾波訊號。本次沒有修改 firmware 的讀取、濾波或 ADC→kPa 公式。
- 每列代表一筆完整有效訊息；相同數值的不同訊息仍分別保存。不新增 BLE 連線或通知 listener，P 查詢仍為每秒一次。獨立校正啟用後另以最多每秒一組 DEBUG／I 查詢確認高度及狀態；額外通訊對實際 P 接收間隔的影響需實機驗證，每秒查詢不等於實測取樣率。
- `timestamp_iso` 是**網頁處理收到完整訊息時**產生的 UTC ISO 時間（Z），不是感測器量測時間。`elapsed_s` 是此接收時刻相對按下開始的 `performance.now()` 差值，範圍 0–30 秒；不強迫樣本落在兩端、不補點或插值。
- 圖表 X 軸固定 0–30 秒，Y 軸標示「壓力（ADC）」；Monitor／Neck／Head 分別沿用紅／綠／藍配色。UI／繪圖以 250 ms 週期刷新，每筆有效訊息則立即保存，不因繪圖節流漏存。這個刷新週期不是感測器或 BLE 的取樣率；右欄既有圖表不變。
- `completed` 僅表示走完 30 秒窗口且沒有已知的上述中斷，不保證取樣數／取樣率，更不代表已驗證辨識穩健性。`ended_early` 是操作者提前結束；`interrupted` 是已知斷線或資料中斷。零樣本不能正常完成或匯出資料列。

## 截圖精靈

`截圖精靈` 是 v3.1 已有的收數區塊，目標是先完成實驗與截圖，之後再依照圖片內容回填 Excel；與本版新增的 Experiment 01 CSV／PNG 收集流程分開使用。

### 截圖精靈操作方式

1. 選擇受試者編號。
2. 選擇固定姿勢最佳高度。
3. 按 `選擇資料夾`，指定本輪截圖儲存位置。
4. 按 `開始` 建立本輪截圖流程。
5. 依照畫面提示切換姿勢與輸入分數。
6. 每一步按 `立即截圖`，系統會自動命名並存檔。

開始後，設定列會收合成：

- `本輪設定已鎖定`
- `資料夾名稱`
- `修改`

使用者若要更換受試者、姿勢或資料夾，可按 `修改` 回到設定狀態。

### 26 張截圖流程

每一個固定姿勢最佳高度，現在固定產生 `26` 張圖。

- `R1`
  - `LOAD-{固定姿勢}`
  - `UNLOAD`
  - 其餘 `4` 個姿勢的 `ACT`
- `R2` 到 `R5`
  - 每一輪各 `5` 張 `ACT`

例如固定姿勢為 `BSHS`：

- `R1 LOAD-BSHS`
- `R1 UNLOAD`
- `R1 ACT-BSHL`
- `R1 ACT-BLHLB`
- `R1 ACT-BLHLC`
- `R1 ACT-BLHL`
- `R2 ACT-BSHS`
- `R2 ACT-BSHL`
- ...
- `R5 ACT-BLHL`

也就是：

- `R1 = 6 張`
- `R2~R5 = 20 張`
- `總共 = 26 張 / 固定姿勢`

### 完整受測者資料與自動整理

一位受測者需要依序完成 `BSHS`、`BSHL`、`BLHLB`、`BLHLC`、`BLHL` 五個固定姿勢最佳高度。每個姿勢會產生 26 張 SVG，完整收集共 130 張，建議整理成以下結構：

```text
Sxx/
├── BSHS/    # 26 SVG
├── BSHL/    # 26 SVG
├── BLHLB/   # 26 SVG
├── BLHLC/   # 26 SVG
└── BLHL/    # 26 SVG
```

收集完成後，可使用 [`NTUST-LSC-Lab/ipillow-data-records-automation`](https://github.com/NTUST-LSC-Lab/ipillow-data-records-automation) 驗證 130 張 SVG，並在保留每次執行前備份的前提下，自動更新 `5pose_calibration`、`Basic_Info` 與 `pose_matrix_5x5` 三份 Excel。

### 分數規則

- `LOAD`：固定為 `10`
- `UNLOAD`：留空
- `ACT`：由收資料人員手動選擇 `0~10`

### 截圖命名規則

目前命名格式為：

```text
{subject_id}_APL-{applied_height_pose}_{stage}_R{repeat_id}_{sequence}.svg
```

例如：

```text
S01_APL-BSHS_LOAD-BSHS_R1_01.svg
S01_APL-BSHS_UNLOAD_R1_02.svg
S01_APL-BSHS_ACT-BSHL_R1_03.svg
S01_APL-BSHS_ACT-BLHLB_R1_04.svg
S01_APL-BSHS_ACT-BLHLC_R1_05.svg
S01_APL-BSHS_ACT-BLHL_R1_06.svg
S01_APL-BSHS_ACT-BSHS_R2_07.svg
```

欄位意義：

- `subject_id`：受試者編號
- `APL-{pose}`：固定姿勢最佳高度來源
- `stage`：`LOAD`、`UNLOAD` 或 `ACT`
- `R{repeat_id}`：第幾輪
- `sequence`：第幾張圖，固定為 `01~26`

## 裝置連線、指令與狀態

此區塊是連線與底層控制入口。

常駐顯示：

- `Connect BLE`：連接 ESP32 BLE。
- `Disconnect`：中斷 BLE。
- `State`：顯示 ESP32 目前 state 名稱。
- `S1` 到 `S6`：顯示馬達/閥門輸出狀態。

### 進階文字指令

`進階文字指令` 預設收合。需要直接送 BLE 指令時展開。

欄位：

- newline 選單

- Uint8Array 輸入框
- `Send Uint8Array`

### 指令合輯

按 `指令合輯` 會開啟 BLE 指令說明視窗。內容包含：

- 高度設定
- 手動/自動模式
- 分類與 PRED
- 壓力與狀態查詢

### ESP32 Manual 控制

`ESP32 Manual 控制` 預設收合，避免大量控制按鈕佔用第一屏。

展開後可操作：

- 進入 ESP32 Manual
- 停止
- Monitor / Neck / Head 單獨充氣
- Monitor / Neck / Head 單獨吸氣
- 全部同時洩氣

- 離開 ESP32 Manual 並回開機流程

## 初始校正

按 `初始校正` 進入校正 modal。

流程：

1. 選擇頸椎狀態。
2. 進入仰躺校正或側躺校正。
3. 使用 `+ / -` 修改 Head / Neck 高度。
4. 按「確定調整」送出高度。
5. 按「完成校正」擷取 anchor。

### 仰躺 BSHS

進入仰躺校正時會送：

```text
INIT,NORM,S
DEBUG
```

`DEBUG` 用途：讀回 ESP32 當下的高度/人體測量學與姿勢流程狀態，供 Web 預填校正欄位與同步監測資訊。

按「確定調整仰躺高度」會送：

```text
SET,NORM,<condition>,S,HEAD,<height_cm>
SET,NORM,<condition>,S,NECK,<height_cm>
```

按「完成校正」會送：

```text
SET,OK
ANCHOR,START,BSHS
```

### 側躺 BLHL

進入側躺校正時會送：

```text
INIT,NORM,L
DEBUG
```

Web 在連線期間也會每 `10 秒` 背景送一次 `DEBUG` 做同步。若 ESP32 當下在 `MANUAL_CONTROL`，常見回覆是：

```text
MANUAL,IGNORED,DEBUG
```

這代表「manual 模式不處理 DEBUG」，是預期行為。

Web 會等待 ESP32 進入 `STANDBY` 後開放側躺微調。若等待逾時，會開放人工微調。

按「確定調整側躺高度」會送：

```text
SET,NORM,<condition>,L,HEAD,<height_cm>
SET,NORM,<condition>,L,NECK,<height_cm>
```

按「完成校正」會送：

```text
SET,OK
ANCHOR,START,BLHL
```

## 高度上下限與 0.5 cm 步進

Web 端與 `pose_pre_v3.1` 韌體共同限制高度：

| 通道 | 最小值 | 最大值 | 步進 |
|---|---:|---:|---:|
| Head | 7.0 cm | 16.0 cm | 0.5 cm |
| Neck | 10.0 cm | 14.0 cm | 0.5 cm |

既有校正／高度控制欄位會：

- 限制在合法上下限內。
- snap 到最接近的 `0.5 cm`。
- `+ / -` 只改 Web UI 暫存值。
- 按「確定調整」後才送出 BLE 指令。

ESP32 端也會再次 clamp / snap，韌體仍是最後安全防線。

Experiment 01「本輪設定」的 Head／Neck 欄位只做紀錄，按「開始記錄」不送高度命令。新增的「獨立校正」區塊使用同一安全範圍，明確按各通道的「套用」才會控制高度。

## 指令說明與範例

### 開機時間設定

這些是舊式指令，仍可用於設定開機固定充氣時間。

| 指令 | 用途 | 範例 |
|---|---|---|
| `SET,MONITOR,<ms>` | 設定 Monitor 開機充氣時間 | `set,monitor,15000,` |
| `SET,NECK,<ms>` | 設定 Neck 開機充氣時間（建議 `>10000 ms`） | `set,neck,12000,` |
| `SET,HEAD,<ms>` | 設定 Head 開機充氣時間（建議 `>30000 ms`） | `set,head,32000,` |
| `RESET` | 非 Manual 狀態下回到 `DRAIN_ALL`，重新跑開機流程 | `reset,` |

常用組合：

```text
set,monitor,15000,
set,neck,12000,
set,head,32000,
reset,
```

前三行送出後會立刻更新 ESP32 變數，但不會立刻重跑流程。`reset,` 會讓流程回到 `DRAIN_ALL`，下一輪才會套用新的開機充氣時間。
建議值：`set,neck,<ms>` 大於 `10000`（10 秒），`set,head,<ms>` 大於 `30000`（30 秒）。

注意：若 ESP32 已在 `MANUAL_CONTROL`，新版 `reset,` 只會停止輸出並停留在 Manual。要離開 Manual 並回開機流程，請使用：

```text
MANUAL,STARTUP,7.0,10.0
```

## 匯出資料

本節說明既有全站 `Export Data`；Experiment 01 另外使用「儲存本輪 CSV＋線圖」，兩者資料來源與欄位格式不同。

CSV 的 `timestamp` 預設為 ISO-8601 UTC（尾碼 `Z`），例如 `2026-05-13T02:21:45.714Z`。在台灣時區（UTC+8）閱讀時，請加 8 小時對照本機時間。

## 常見問題

### 按下 Send Text 沒反應

先確認：

- 已按 `Connect BLE`。
- 訊息紀錄有顯示 `Connected!`。
- 指令最後有換行。newline 留空時 Web 會自動補 `\n`。
- ESP32 是否仍在 `MANUAL_CONTROL`，Manual 中部分一般指令會被忽略。

### `set,monitor,...` 是否還能用

可以。它會立即更新 `MonitorInitialFillTime`。但若要重新套用到開機流程，通常需要再送 `reset,`。

### `reset,` 是否等於回開機流程

非 Manual 狀態下，是。
Manual 狀態下，不是。Manual 狀態下要回開機流程請用：

```text
MANUAL,STARTUP,<head_cm>,<neck_cm>
```

### 0.5 cm 高度是否會送到 ESP32

既有校正／高度控制與 Experiment 01 新增的獨立校正，按確認／套用後會送出；Web 與 ESP32 `pose_pre_v3.1` 均支援 0.5 cm 步進。「本輪設定」欄位仍只做紀錄。

### `ESP32 Manual 狀態：ESP32 Manual 忽略指令：DEBUG` 是不是壞掉

不是。Web 會定期送 `DEBUG` 同步資料；但 ESP32 在 `MANUAL_CONTROL` 只接受部分指令，`DEBUG` 會回 `MANUAL,IGNORED,DEBUG`。若要停止這類訊息，請先離開 manual（例如送 `MANUAL,STARTUP,<head_cm>,<neck_cm>`）。

### 如何確認模式切換成功

看「訊息紀錄」中的回覆：

```text
FEATURE,STATUS,...
CLASSIFY,OK,START
PRED,OK,START
PRED,OK,STOP
```

### 如何確認 Manual 指令成功

看「訊息紀錄」或 `ESP32 Manual 狀態`：

```text
MANUAL,OK,ENTER
MANUAL,OK,STOP
MANUAL,OK,FILL,HEAD
MANUAL,OK,DRAIN,ALL
MANUAL,OK,STARTUP,7.0,10.0
```
